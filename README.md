# SAMSAL Supply & Distribution Limited - Corporate Website (Version 2)

Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 3 · Lucide icons · Vercel-ready.
No database. The only server code is one API route that emails quotation requests.

---

## 1. Run it locally

Requires Node.js 20.9 or newer.

```bash
npm install
cp .env.example .env.local      # then fill in values (all optional for local dev)
npm run dev                     # http://localhost:3000
npm run build && npm start      # production check
```

In development, if email is not configured, submitting a form succeeds and prints the enquiry in the terminal.
In production, an unconfigured form returns a clear error (it never pretends to have sent).

## 4. Environment variables

Set in `.env.local` for development and in **Vercel > Project > Settings > Environment Variables** for production.
See `.env.example` for the full list.

| Variable | Purpose | Required |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Primary domain, e.g. `https://samsal.co.ke` (canonical URLs, sitemap, social previews) | Yes |
| `RESEND_API_KEY` | Resend API key (server-side only, never exposed) | Yes, for email |
| `QUOTE_TO_EMAIL` | Where enquiries are delivered (comma-separate several) | Yes, for email |
| `QUOTE_FROM_EMAIL` | Sender, e.g. `SAMSAL Website <quotes@samsal.co.ke>` | Recommended |
| `NEXT_PUBLIC_CONTACT_PHONE` | Shown on Contact page and footer | When confirmed |
| `NEXT_PUBLIC_CONTACT_EMAIL` | Shown on Contact page and footer | When confirmed |
| `NEXT_PUBLIC_WHATSAPP_NUMBER` | Digits only, e.g. `2547XXXXXXXX`. WhatsApp buttons appear only when set | When confirmed |
| `NEXT_PUBLIC_BUSINESS_HOURS` | e.g. `Mon-Fri 8:00-17:00` | When confirmed |
| `FORM_TOKEN_SECRET` | Long random string (`openssl rand -hex 32`) that signs the anti-bot timing token. Server-side only | Strongly recommended |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Shared rate limiting across serverless instances (free Upstash Redis; the Vercel Marketplace adds them automatically) | Strongly recommended |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` | Optional Cloudflare Turnstile CAPTCHA | Optional |

Variables beginning `NEXT_PUBLIC_` are visible in the browser by design (they are public contact details).
Secrets (`RESEND_API_KEY`, `TURNSTILE_SECRET_KEY`) have no such prefix and stay on the server.

## 5. Email setup (Resend)

1. Create a free account at https://resend.com.
2. **Domains > Add Domain** > `samsal.co.ke`. Resend shows DNS records (SPF, DKIM, optionally DMARC). Add them at your DNS provider and click Verify.
3. **API Keys > Create API Key** (sending access). Copy it.
4. In Vercel set `RESEND_API_KEY`, `QUOTE_TO_EMAIL` (the inbox that should receive quotes) and `QUOTE_FROM_EMAIL` (an address on the verified domain).
5. Redeploy, submit a test quote, and confirm it arrives. Replying to the email replies to the customer.

Until your domain is verified you can test with `QUOTE_FROM_EMAIL="SAMSAL Website <onboarding@resend.dev>"`; Resend delivers those only to your own account email.

## 6. Deploy to Vercel

1. Push this folder to a GitHub repository (`git init`, commit, push).
2. At https://vercel.com choose **Add New > Project**, import the repo. Framework is auto-detected as Next.js; leave build settings as default.
3. Add the environment variables from section 4 (Production, and Preview if wanted).
4. Click **Deploy**. You get a `*.vercel.app` URL to review before pointing the real domain.

## 7. Domains and DNS (samsal.co.ke primary, samsal.com redirects)

1. In Vercel: **Project > Settings > Domains > Add** `samsal.co.ke`. Also add `www.samsal.co.ke` and `samsal.com` (and `www.samsal.com`).
2. Vercel shows the exact DNS records to create. Typically:
   - Apex (`@`): `A` record > `76.76.21.21`
   - `www`: `CNAME` > `cname.vercel-dns.com`

   Use whatever values the Vercel dashboard displays for your project; they take priority over these examples.
3. Create the records where each domain is registered/managed (for `.co.ke`, your KENIC-accredited registrar; for `.com`, its registrar). Alternatively point the domain's nameservers at Vercel.
4. In Vercel set **samsal.co.ke** as the primary domain and configure `samsal.com`, `www.samsal.com`, and `www.samsal.co.ke` to **redirect (permanent)** to `https://samsal.co.ke`. The same redirects are also coded in `next.config.mjs` as a safeguard.
5. Wait for DNS (minutes to a few hours). Vercel issues HTTPS certificates automatically.
6. Set `NEXT_PUBLIC_SITE_URL=https://samsal.co.ke` and redeploy so canonical URLs, sitemap and social previews use the final domain.
7. Submit `https://samsal.co.ke/sitemap.xml` in Google Search Console, and claim a Google Business Profile for local Nairobi visibility once you have a confirmed address/phone.

## 8. Security of the quotation form (Version 2)

- **Attachments are verified by content, not just name.** The server checks the extension, the browser-declared MIME type
  and the file's real bytes (PDF, PNG, JPEG signatures; Word/Excel packages; legacy .doc/.xls; valid UTF-8 text for
  CSV/TXT). A renamed .exe, a PNG named .pdf, or a fake .docx is rejected. 4 MB limit enforced before and after parsing.
- **Signed timing token.** The server issues an HMAC-signed "form opened" timestamp (`/api/quote/token`); a bot cannot forge
  it, so instant submissions are refused. Requires `FORM_TOKEN_SECRET`.
- **Shared rate limiting.** With Upstash configured, limits (5 per 10 minutes per IP) hold across all serverless instances.
  Without it, a per-instance memory limiter is used and a warning is logged; this is weaker.
- **Also:** honeypot, link-stuffing check, same-origin check, optional Turnstile, input sanitisation, HTML-escaped emails.
- **Honest delivery.** Success is reported only when Resend accepts the email and returns a message id. Misconfiguration or a
  provider error returns an error to the visitor. In development (not production) the form says plainly that nothing was
  emailed.
- Secrets (`RESEND_API_KEY`, `FORM_TOKEN_SECRET`, `UPSTASH_*`, `TURNSTILE_SECRET_KEY`) have no `NEXT_PUBLIC_` prefix and never
  reach the browser.

## 8b. Older notes: spam protection (Version 1)

- Server-side validation and sanitisation of every field (the browser checks are only for convenience).
- Honeypot field, minimum-fill-time check, per-IP rate limit (5 submissions / 10 min).
- Optional Cloudflare Turnstile (free) : set the two keys to enable.
- Attachments: type allow-list, 4 MB limit (Vercel request-body limit is about 4.5 MB), safe file names; sent straight to email and **not stored**.
- No customer data is stored: the enquiry exists only in the delivered email.
- Security headers (`nosniff`, frame, referrer, permissions policy). API keys are server-side only.
- The in-memory rate limiter is per server instance. For stricter limits add Upstash Redis / Vercel KV.

## 9. Legal pages

`/privacy` and `/terms` are DRAFTS that must be reviewed by a qualified Kenyan advocate or data protection adviser. While
`legal.reviewed` is `false` in `src/config/site.ts`, both pages show a draft banner, are `noindex` and are left out of the
sitemap. After approval: complete the [bracketed] items, set `reviewed: true`, and redeploy. The pages do not claim legal compliance.

## 10. Images

Images are original vector illustrations (`public/images/illustrations`), configured in one place:
`src/config/images.ts`. They are NOT photographs. See `docs/PHOTOGRAPHY.md` to swap in real, licensed photography.

## 11. Information still needed from the business (marked CONFIRM in code)

- Telephone, business email, WhatsApp number, business hours, and (if wanted) physical address and social profile URLs.
- Real photography (see `src/config/images.ts`). None is bundled; slots show a clean branded panel meanwhile.
- Real product details: pack sizes, specifications, brands the business is happy to name, and product photos.
- Whether delivery beyond Nairobi, credit terms, or any licences should be mentioned on the Services page.
- Approval before publishing the company profile, catalogue or supplier documents (add to `/public/documents` and `src/config/documents.ts`).
- Final logo artwork, if one exists.
- Legal pages (Privacy Policy / Terms) : recommended before launch, particularly because the forms collect personal data (Kenya Data Protection Act). Have these reviewed by a qualified adviser.

## 12. Structure

```
src/
  app/            pages (/, about, products, services, industries, contact, quote), api/quote, sitemap, robots
  components/     Header, Footer, Logo, ProductCard, QuoteForm, WhatsAppButton, shared UI
  config/         site, navigation, products, services, industries, documents, images
  lib/            validation (shared client+server), rate-limit, seo helpers
public/logo/      logo files
scripts/          brand asset generator
```

The folder layout leaves room for future modules (enquiry dashboard, supplier database, quotation and purchase-order
management, inventory, customer accounts, tender tracking) without restructuring: add routes under `src/app/admin/*`
and a database when genuinely needed.
